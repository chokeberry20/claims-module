# Architecture & Business Decisions

_Status: revision 4 (2026-11-22). Each entry gives the issue, its source (S = Functional Spec section or rule, B = Assessment Brief section) and the resolution, including the rationale._

## D-00 Precedence rule
The **spec (FRS) wins on business rules**. The **brief wins on stack, architecture, deliverables and deployment**. Where the brief adds an endpoint, field or entity the spec lacks, we add it. Real conflicts are resolved below.

| D-16 | Adjust semantics: is the amount a delta or a target? **D-41 Hangfire dashboard protection, details:**
- A custom `BasicAuthDashboardFilter : IDashboardAuthorizationFilter` parses the `Authorization: Basic` header and compares the credentials in constant time (`CryptographicOperations.FixedTimeEquals`).
- On failure it sets 401 with `WWW-Authenticate: Basic realm="Hangfire"`, so the browser shows its login prompt. A filter that only returns false gives a bare 401 with no prompt.
- HTTPS only (App Service HTTPS-only, plus HSTS). The dashboard antiforgery stays enabled.
- If the password isn't configured, the dashboard is **not mapped** at all (fail closed). In Development, local requests are allowed as well.
- No extra package is needed. The SPA doesn't link to the dashboard; the README documents the URL and where the credentials live.

More assumptions go to ai-log:
- Single currency (USD).
- One organisation seeded, with its ID in config.
- Multiple claimants are allowed.
- The audit OldValue for a rejection carries the reason, per S14.1.
- Each transition writes STATUS_CHANGED plus the specific CLAIM_CLOSED/REOPENED event.
- Extra events: CLAIM_UPDATED, POLICY_LINKED, HANDLER_ASSIGNED, WARNINGS_ACKNOWLEDGED, RESERVE_LIMIT_OVERRIDE_SET, GL_POSTING_RETRY_REQUESTED.


## Deliberate deviations from the literal spec (summary)
- **D-19:** the aggregate limit uses the gross total (Indemnity + Expense + ALAE) instead of "across all components".
- **D-23:** ClaimAuditLog has no soft-delete or UpdatedAt columns (immutable log).
- **D-29:** the blob name adds a `{documentId}-` prefix to avoid overwrites.
- **D-13:** SLA breach is a flag, not a status (brief vs spec).
- **D-07:** the NO_CLAIMANT Critical can't be waived.
- **D-05:** request-level Criticals (BR-C-01 future loss date, BR-C-05 unknown or inactive cause code, BR-C-07 description < 20 chars) get **422 and nothing is saved**. S5.4 says Criticals leave the claim "in Draft". Only state-level Criticals (e.g. NO_CLAIMANT) are saved on a Draft claim.
- **D-24:** a user whose role can't approve at all (handler) gets **403 Forbidden**, not the **422** that S8 lists ("Your role does not have authority…"). The 422 is kept for a supervisor approving more than $100k and for self-approval.
- **D-43:** the reserve history entity is called `ReserveTransaction` in C# and maps to the `ReserveHistory` table (S15.3 says entities match table names). The spec calls these rows transactions, and names already differ by plurality elsewhere.
- **D-44:** reject is limited by the approver's amount authority (supervisors only up to $100,000, per S3). S10.2 says only "Requires Supervisor or Manager role" for reject, with no amount limit.
